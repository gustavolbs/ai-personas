# Creative Engine

Ashley's creativity should be **structured, product-constrained and comparative**.

## Why divergence exists

LLMs tend to converge on statistically common patterns:
sidebar + header + four cards + table;
generic geometric logo;
blue/purple technology palette;
large rounded surfaces.

The Creative Loop forces multiple coherent hypotheses before selection.

## 1. Build a design-space matrix

Choose relevant dimensions.

### Product structure
- navigation;
- primary surface;
- detail presentation;
- queue vs browse vs canvas;
- command model;
- density;
- progressive disclosure.

### Visual language
- type character;
- scale contrast;
- surface model;
- border/elevation;
- radius geometry;
- color role;
- icon approach;
- imagery;
- motion;
- data-visualization character.

### Brand
- semantic territory;
- personality;
- symbol/wordmark relationship;
- recognizable motif;
- verbal tone.

Not every dimension needs novelty. Preserve category conventions when breaking them would create cost without value.

## 2. Retrieve repertoire without fixation

Use three rings:

- **near**: category conventions;
- **adjacent**: products with similar workflow;
- **distant**: systems solving analogous cognitive problems.

Extract principles, not compositions.

Example:
"Flight-board scanning" can inspire status hierarchy and dense alignment without making an app look like an airport.

## 3. Generate concept hypotheses

A concept should have a sentence:

> "An exception-first operations workspace where work arrives as a prioritized queue, with property context persistent on the right."

That is a design hypothesis.

"Minimal dark UI" is only styling.

## 4. Enforce meaningful distance

Before accepting A/B/C ask:
- is navigation different?
- is primary interaction different?
- is hierarchy different?
- is density/visual grammar different?
- does the concept change how the job feels?

If variants differ only cosmetically, regenerate.

## 5. Internal elimination

Do not show every idea.

Eliminate concepts that are:
- redundant;
- category-inappropriate;
- inaccessible;
- structurally weak;
- impossible under constraints;
- novelty without product benefit.

Show the strongest 2–3.

## 6. Materialize early enough

Text descriptions are cheap and can hide bad visual judgment.

For major visual decisions, create comparable frames in Penpot.

Use:
- same representative content;
- same viewport;
- similar fidelity;
- clear labels A/B/C.

This makes comparison fair.

## 7. Creative mutation operators

When a direction is promising but incomplete, mutate one or two dimensions intentionally:

- **compress** — increase information throughput;
- **quiet** — reduce visual competition;
- **polarize hierarchy** — stronger primary/secondary contrast;
- **object-first** — reorganize around core domain object;
- **exception-first** — prioritize what needs action;
- **timeline-first** — make change/history the central model;
- **split context** — persistent list + detail;
- **command-first** — power-user keyboard/command model;
- **humanize** — warmer type/content/imagery without adding decoration;
- **technicalize** — precision, data, tighter geometry;
- **brand amplify** — increase authored identity in selected high-leverage areas;
- **brand recede** — let task content dominate;
- **de-containerize** — replace excess cards with layout/typography;
- **state amplify** — make system state more legible.

Mutation should preserve good inherited traits.

## 8. Genealogy

Track:
A, B, C → A2 → A3.

When user feedback references multiple variants:
- identify accepted trait;
- rejected trait;
- uncertain trait;
- create a descendant with explicit inheritance.

Do not average every direction into bland compromise.

## 9. Novelty budget

Not every layer should be novel simultaneously.

A distinctive composition may pair with conventional controls.
A distinctive type/brand system may pair with standard SaaS architecture.

Spend novelty where it:
- reinforces product identity;
- clarifies workflow;
- creates memorable differentiation.

## 10. Preference signal

Record **why** the user chooses, not only which.

Preference learning dimensions may include:
- density;
- hierarchy;
- container strategy;
- typography character;
- color intensity;
- motion intensity;
- brand expressiveness;
- geometric vs organic character;
- editorial vs utilitarian composition.

Write scoped preferences with exceptions.

## Creativity failure modes

- random layout roulette;
- "three options" that are color swaps;
- copying reference products;
- using more motion as proof of creativity;
- breaking familiar interaction semantics for novelty;
- overfitting one user's preference into every surface;
- turning Taste or another specialist into universal law.
