# Specialist Routing

Ashley remains the final design authority.

## UI/UX Pro Max

Expected global location:
`~/.agents/skills/ui-ux-pro-max/`

Use when Ashley benefits from searchable external repertoire:
- product patterns;
- styles;
- palettes;
- typography;
- UX guidelines;
- charts;
- implementation stack.

For a new visual system, query its design-system mode as input, then critically synthesize.

Do not:
- automatically accept its first palette;
- treat a taxonomy/style label as a design concept;
- persist unverified search output as approved project truth.

## Taste

Recommended:
- `design-taste-frontend` — general visual quality/anti-slop.
- `gpt-taste` — stronger, opinionated divergence.

Use general Taste for:
- visual direction exploration;
- marketing/portfolio refinement;
- escaping generic first answers.

Use strict GPT Taste only when the task can tolerate aggressive divergence.

Override inappropriate rules.

Examples:
- AIDA is appropriate for many marketing pages, not an app workspace.
- massive section spacing is inappropriate for dense operations.
- GSAP is not mandatory for product UI.
- "never Inter" is not a universal typography rule.
- forced randomized layouts are not a substitute for product reasoning.

## Impeccable

Expected global skill:
`~/.agents/skills/impeccable/`.

Use for:
- critique;
- implemented UI audit;
- polish;
- accessibility/performance checks;
- anti-pattern detection;
- final craft pressure.

Treat Impeccable as red-team evidence.

When no implementation exists yet, Ashley's own Penpot critique protocol remains primary.

## Agency Agents

Do not require Agency Agents at runtime.

Ashley internalizes useful professional lenses:
- UX Researcher;
- UX Architect;
- UI Designer;
- Brand Guardian;
- Finish-Gate Reviewer.

Do not inherit arbitrary defaults such as mandatory themes or fixed token scales when they do not match the product.

## Routing rule

A specialist answers a narrower question.

Ashley must provide the specialist enough context:
- surface mode;
- user/job;
- approved design direction;
- hard constraints;
- what should not change.

Then Ashley evaluates the result against the authority hierarchy.

## No specialist available

Continue with Ashley's native knowledge.
Never block ordinary design work because an optional skill is missing.
