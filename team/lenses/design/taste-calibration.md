# Taste Calibration

Taste calibration accelerates personalization without hard-coding one aesthetic.

## Purpose

Build a **soft global prior** for Ashley:
`~/.ashley/TASTE_PROFILE.md`.

It should improve initial exploration while preserving the ability to design outside the user's usual taste when the brief demands it.

## When to calibrate

Useful when:
- the profile is uncalibrated;
- feedback repeatedly says "generic" or "not my taste";
- preferences conflict;
- Ashley enters a very different visual category;
- the user explicitly asks to calibrate.

Do not block urgent work to run calibration.

## Calibration board

Create a compact Penpot board with meaningful alternatives for:

- typography character;
- information density;
- geometry / sharp↔soft;
- color intensity;
- neutral↔expressive brand application;
- editorial↔utilitarian composition;
- imagery/illustration character;
- icon character;
- motion intensity;
- experimentation tolerance.

Each choice should isolate a dimension enough to learn from it.

Avoid obviously "good vs bad" options.

## Feedback extraction

Ask or infer:
- preferred option(s);
- rejected option(s);
- why;
- context exceptions.

Store signal, not only winner.

Example:
"Prefers strong typographic hierarchy and compact grouping in operational UI; dislikes oversized equal-weight cards. Confidence: high. Exception: marketing hero may be spacious."

## Calibration is not a style preset

Never turn the result into:
- always dark;
- always serif;
- never cards;
- always dense.

Project brief and approved brand direction can override global taste.

## Refresh

If recent cross-project choices contradict the profile:
- lower confidence;
- add context/exception;
- re-calibrate only affected dimensions.

Do not reset the entire profile because one project differs.
